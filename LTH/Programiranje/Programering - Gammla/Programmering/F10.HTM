Det har gått några veckor sedan förra föreläsningen, om du inte känner dig helt säker på det som tidigare behandlats i kursen är det lämpligt att repetera, särskilt följande grundläggande begrepp är viktiga denna vecka:

Implementation av egna klasser

Vi har under läsperiod 2 använt färdigskrivna klasser vid många tillfällen, vi skall nu lära oss att skriva egna (vi säger att vi implementerar egna klasser).

En klass beskriver hur ett en viss sorts objekt fungerar, vi deklarerar den genom att skriva: 

    class Klassnamn {

        deklarationer
    }
där vi har två typer av deklarationer:
  • attribut, och
  • operationer (metoder).
Klassnamn skall normalt inledas med stor bokstav (detta är ingen regel, men en allmänt vedertagen konvention - vi kommer att följa den i kursen), vi skriver därför Turtle, SimpleWindow, Account etc.

Attribut (tillståndsvariabler)

Vi har sagt att objekt kan ha olika tillstånd, tillståndet för en sköldpadda (Turtle) beskrivs bland annat av:
  • dess x- och y-koordinater,
  • dess riktning, och
  • pennans läge (uppe/nere).
För att hålla reda på sitt tillstånd måste varje sköldpadda lagra ovanstående värden i lämpliga variabler. Den gör det i så kallade tillståndsvariabler (vi kallar ofta tillståndsvariablerna för attribut, eftersom de beskriver objekten).

Tillståndsvariablerna deklareras inne i klassdeklarationen, i en klass A skulle ett heltalsattribut a och ett reellt attribut b deklarerats på följande sätt: 

    class A {
    
        int a;
        double b;
    
        // resten av klassen
    }
Under övningen denna vecka skall ni själva implementera klassen Turtle, så för att inte förstöra övningen introducerar vi en ny klass som exempel.

Antag att vi i våra program vill kunna kasta med tärningar. Det finns ingen standardklass för tärningar i Java, men vi kan själva skriva en. Vi får då först fundera över vad vi vill kunna göra med objekten, dvs vilken klasspecifikation klassen skall ha. Vi kan exempelvis välja: 

    class Die {

        /**
         * Skapar en sex-sidig tärning (konstruktor).
         */
        Die();

        /**
         * Kastar tärningen.
         */
        void roll();

        /**
         * Returnerar det antal prickar som tärningen visar efter
         * det senaste kastet.
         */
        int getValue();
    }
Vi kan tyvärr inte använda namnet throw för operationen som skall kasta tärningen, throw är ett reserverat ord i Java (det används för felhantering, mer om det senare i kursen).

Ett program som skapar en tärning och räknar hur många gånger tärningen måste kastas innan summan av antalet prickar överstiger 100 kan då skrivas: 

    public static void main(String[] args) {
        Die die = new Die();
        int sum = 0,
            count = 0;
        while (sum < 100) {
            die.roll();
            sum += die.getValue();
            count++;
        }
        System.out.println("Jag behövde " + count + " kast.");
    }
Hur kan vi då beskriva tillståndet hos vår tärning? Vi kan naturligtvis hålla reda på vilken färg tärningen har, vilken storlek den har, var den befinner sig (x-, y- och z-koordinater i rummet), etc, men det enda vi egentligen intresserar oss för är hur många prickar den visar efter senaste kastet (dvs hur många prickar som är vända uppåt!). I vår modell av en tärning skalar vi alltså bort all för uppgiften ovidkommande information.

Antalet prickar kan beskrivas med en heltalsvariabel, så vi inför attributet (tillståndsvariablen) value. Vi gör det genom att inne i klassdeklarationen skriva: 

    class Die {

        int value;    // deklaration av tillståndsvariabeln 'value'

        // övriga deklarationer
    }
Denna variabel skiljer sig på flera punkter från de variabler vi använt tidigare. I ett program som 
    public class Sample {
    
        public static void main(String[] args) {
            int n;
            n = Keyboard.readInt("Ange n: ");
            // ...
        }
    }
är n en lokal variabel, deklarerad inne i huvudprogrammet. Den lokala variabeln n är inte knuten till något objekt, och försvinner så snart operationen main nått sin sista rad (mer om detta nedan).

Attributet value är deklarerat ute i klassen Die, det innebär att varje tärningsobjekt får en egen tillståndsvariabel value, och att denna variabel finns kvar så länge objektet finns kvar.

När vi skapar nya tärningar får vi följande objekt och variabler i minnet: 

    public static void main(String[] args) {
        Die d1 = new Die(),
            d2 = new Die(),
            d3 = new Die();
        // ...
    }

Varje tärning har sina egna tillståndsvariabler.

Det finns ingen gräns för hur många attribut vi kan ha i en klass, och för vilka typer attributen kan ha. Vi kan ha heltalsattribut, logiska attribut, vektorer och vanliga referenser etc.

Attribut, till skillnad från lokala variabler, får automatiskt startvärden. Heltalsattribut får värdet 0, reella variabler värdet 0.0, logiska variabler värdet false och vektorer och referenser värdet null.

    Deklarera dem sedan inne i en i övrigt tom klass Turtle.

Operationer (metoder)

Vi har tidigare sagt att vi kan betrakta operationerna som anges i klasspecifikationen som sätt att manipulera tillståndet hos ett givet objekt, vi skall nu se hur vi skriver programkod för att göra just detta.

Vi delar upp operationerna i tre olika kategorier:

  • konstruktorer, som ger objekten väldefinierade starttillstånd,
  • operationer som bara ändrar objektens tillstånd, och
  • operationer som returnerar information om objektens tillstånd.
Genmensamt för dem alla är att de består av vanliga programrader, precis som de program ni skrivit tidigare i kursen. Vi skriver operationerna mellan ett omgivande par klamrar ({ och }, på samma sätt som i era huvudprogram), och vi använder lokala variabler, tilldelningar, if-, for- och while-satser som vanligt. Skillnaden nu är att vi förutom våra lokala variabler även har tillståndsvariabler (attribut) att arbeta med.

Operationer kallas med ett annat ord för metoder.

Konstruktorer

När vi skapar nya objekt anropas en konstruktor i klassen. Meningen med konstruktorn är att ge ett objekt ett lämpligt initialtillstånd. Vi har redan nämnt att attributen automatiskt får startvärden (0, 0.0, false, eller null) - om vi vill ge dem andra startvärden kan vi göra det i konstruktorn. Konstruktorerna har alltid samma namn som klassen själv, och är i regel de enda operationer som skrivs med stor begynnelsebokstav.

I klassen Die var konstruktorn deklarerad som Die(), dvs utan några parametrar (mer om parametrar till operationer nedan). Vi skriver den därför på följande sätt: 

    class Die {
    
        int value;
        
        public Die() {
            // här ger vi objektet lämpligt starttillstånd
        }
    }
Programkoden i konstruktorn anropas precis efter att ett nytt objekt har skapats: 
    Die die = new Die();  // en tärning skapas, och konstruktorn anropas
När konstruktorn anropas har attributen redan fått sina automatiska startvärden (i detta fall har attributet value fått värdet 0).

Eftersom 0 inte är ett giltigt värde för en tärning kan vi i konstruktorn sätta ett lämpligt giltigt värde på attributet value i denna (den nyskapade) tärningen, exempelvis 1, genom att skriva: 

        public Die() {
            this.value = 1;
        }
Man behöver inte skriva ut this, de flesta skriver istället bara 
        public Die() {
            value = 1;
        }
där det underförstått är objektet 'this' vars attribut value får värdet 1.

Jag kommer i denna kurs att skriva ut this överallt, för att tydligt markera vad som är ett attribut. (Denna egenhet är jag ganska ensam om, Javas kodningsstandard säger ingenting om huruvida man skall skriva ut this eller inte - i vissa fall måste man göra det, jag gör det alltid. Jag tycker även att det finns en pedagogisk poäng med att skriva ut this, många förvirras av att klassen på en gång beskriver ett objekt och samtidigt samtliga objekt av den aktuella klassen, genom att markera this framgår att vi utför något på ett enstaka objekt.)

void-operationer och lokala variabler

Vi har tidigare sett att en del operationer bara ändrar på ett objekts tillstånd, operationen roll() i klassen Die är ett exempel på detta. När vi kastar tärningen ändrar den tillstånd, vill vi veta något om det nya tillståndet får vi använda operationen getValue() som returnerar ett heltal (antalet prickar).

En operation som bara ändrar tillståndet hos ett objekt deklareras som void, så roll()-operationen skrivs: 

    void roll() {
        // här skriver vi programrader för att rulla tärningen
    }
Alla operationer (utom konstruktorerna) deklareras i regel med liten begynnelsebokstav.

Om vi vill få slumpmässiga värden när vi kastar tärningen (och det vill vi!) kan vi använda en slumptalsgenerator inne i operationen roll(). Precis som vanligt, när vi använder slumptalsgeneratorer, deklarerar vi en referens till generatorn och använder den sedan för att dra ett slumptal i intervallet 1..6 som vi lagrar i attributet value: 

    void roll() {
        RandomNumberGenerator rng = new RandomNumberGenerator();
        this.value = rng.randInt(1,6);
    }
Här är rng en lokal variabel som fungerar precis som de variabler ni använt tidigare - alla variabler som använts hittills i kursen har varit lokala variabler i huvudprogrammet.

Lokala variabler finns tillgängliga så länge det block de deklarerats i körs, sedan 'försvinner' de. Referensvariabeln rng ovan finns alltså bara medan roll()-operationen körs, därefter försvinner den och därmed det objekt den refererar till (eftersom rng var den enda referensen till denna slumptalsgenerator). Lägg dock märke till att attributet value i tärningen finns kvar även efter att roll()-operationen körts färdigt, attributen finns kvar så länge objekten de tillhör finns kvar.

Man kan ha lokala variabler i alla operationer, även i konstruktorer (även om vi inte hade något i exemplet ovan).

Man får ge en lokal variabel samma namn som ett attribut i samma klass (man bör dock vara försiktig med detta eftersom det är en potentiell felkälla!). Om det finns både lokala variabler och attribut med samma namn används normalt den 'närmast deklarerade' variabeln, dvs den lokala variabeln, såvida man inte markerar med this att det är attributet som avses (eftersom jag alltid sätter ut this får jag inga problem med detta).

Exempel
I operationen op() nedan finns fyra variabler: 

class A {

    int a,b;

    void op() {
        int b, c;    // vi har nu fyra variabler:
                     // * attributen a och b (tillståndsvariabler)
                     // * de lokala variablerna b och c

        a = 1;       // attributet a får värdet 1
        b = 2;       // den lokala variabeln b får värdet 2,
                     // attributet b påverkas inte
        this.b = 3;  // attributet b får värdet 3
        c = 4;       // den lokala variabeln c får värdet 4
    }
}
För att undvika missförstånd kommer jag att skriva: 
class A {

    int a,b;

    void op() {
        int b, c;    // vi har nu fyra variabler:
                     // * attributen a och b (tillståndsvariabler)
                     // * de lokala variablerna b och c

        this.a = 1;  // attributet a får värdet 1
        b = 2;       // den lokala variabeln b får värdet 2
        this.b = 3;  // attributet b får värdet 3
        c = 4;       // den lokala variabeln c får värdet 4
    }
}
dvs jag markerar alltid med this när jag vill använda ett attribut (dvs i fallet ovan hade jag inte behövt skriva this.a, men gjorde det ändå)..

Om att anropa andra operationer

I en operation kan vi även anropa andra operationer på det aktuella objektet, om vi i konstruktorn vill ge tärningen ett slumpmässigt startvärde kan vi göra det genom att kasta tärningen: 
    Die() {
        this.roll();
    }
vilket innebär att vi utför operationen roll() på det objekt som vi håller på att initiera. Även här kan man utelämna ordet this, dvs vi hade kunnat skriva: 
    Die() {
        roll();
    }
Vi har tidigare i kursen sagt att alla operationer måste utföras på givna objekt, i det första fallet ovan är det uppenbart att roll() utförs på ett objekt (this), i det andra fallet är det kanske inte lika uppenbart. Ni får själva välja om ni vill skriva ut this eller inte, Javas officiella kodstandard säger inte något om hur man bör göra.

Att anropa andra operationer är ett bra sätt att strukturera sin programkod, vi kommer att diskutera detta mer senare i kursen.

Något om klasser i sin helhet och 'this'

Operationen roll() är deklarerad i klassen Die, men den utförs bara för ett givet Die-objekt åt gången (this). När vi skriver 
    Die die = new Die();
    die.roll();
är det tärningen som die refererar till som manipuleras (this kommer alltså att referera till samma objekt som die). Vi kommer att diskutera detta ganska ingående under föreläsningen.

Referensen this är alltså alltid det objekt vi utför aktuell operation på! (det finns därför inget this i ett huvudprogram, mer om detta senare i kursen)

Kontrollfrågor

  1. Rita en figur över variablerna och objekten (med tillhörande attribut) i följande programavsnitt. Vilket objekt är 'this' när roll() anropas för första gången? 
        Die d1 = new Die(),
        d2 = new Die();
    d2.roll();   // här anropas roll() för första gången
  2. Vilka variabler finns tillgängliga när programmet når den andra raden i roll()-operationen inne i klassen Die?

Operationer som returnerar värden

När vi anropar operationen getValue() vill vi få tillbaka ett heltal, exempelvis: 
    Die die = new Die();
    die.roll();
    int nbrOfDots = die.getValue();
Vi deklarerar därför getValue() som en heltalsoperation. Det blir den om vi skriver: 
    int getValue() {
        // rader som behövs för att returnera värdet...
    }
Vi får operationen getValue() att returnera ett värde genom att inne i operationen skriva 'return värde'. Eftersom det värde getValue() skall returnera helt enkelt är värdet på attributet value blir implementationen väldigt enkel: 
    int getValue() {
        return this.value;
    }
Det är viktigt att det värde som returneras har samma typ som den vi givit operationen, i detta fall är attributet value deklarerat som ett int, precis som operationen getValue(). Man kan i Java returnera vilken typ av värden som helst, både primitiva värde (heltal, reella tal, logiska variabler, tecken etc) och referenser (referenser till objekt eller vanliga vektorer).

När programmet når en return-sats avbryts den aktuella operationer, eventuella satser efter kommer inte att exekveras: 

    int getValue() {
        return this.value;
        System.out.printlnt("Här kan jag skriva vad som helst...");
    }
Utskriften efter return-satsen ovan kommer alltså inte att utföras (kompilatorn kommer att se detta och ge ett felmeddelande).

Parametrar till operationer

Om vi, av någon anledning, vill ha en operation som vänder tärningen så att ett givet antal prickar vänds uppåt, så måste vi på något sätt tala om för tärningen hur många prickar som skall visas.

Vi kan göra det genom att införa en operation setValue, där vi har en parameter newValue som talar om hur många prickar som skall visas. Operationen kan implementeras på följande vis: 

    void setValue(int newValue) {
        this.value = newValue;
    }
eller, om vi är misstänksama: 
    void setValue(int newValue) {
        if (newValue < 1) {
            this.value = 1;
        } else if (newValue > 6) {
            this.value = 6;
        } else {
            this.value = newValue;
        }
    }
En parameter är alltså ett värde som skickas in till en operation, om någon skriver 
    Die die = new Die();
    // ...
    die.setValue(4);
så kommer operationen setValue att anropas för tärningen die, parametern newValue får värdet 4.

Parametrarna fungerar precis som vanliga lokala variabler, men de får ett startvärde när operationen anropas. Det är tillåtet att ändra värdet på en parameter, dess värde ändras precis som värdet på en lokal variabel skulle ändrats, och när operationen kört färdigt försvinner dess värde. Vi skulle kunnat skriva den misstänksamma varianten av setValue ovan på följande sätt: 

    void setValue(int newValue) {
        if (newValue < 1) {
            newValue = 1;
        } else if (newValue > 6) {
            newValue = 6;
        }
        this.value = newValue;
    }
På sista raden lagras det nya värdet på newValue i attributet value, sedan avslutas operationen och variabeln newValue försvinner. Det är ganska vanligt att parametrar får samma namn som attribut, exempelvis hade det varit naturligt att kalla parametern till setValue för value: 
    void setValue(int value) {
        this.value = value;
    }
I detta fall måste vi skriva ut this. när vi skall ge attributet value sitt nya värde, om vi skriver 
    void setValue(int value) {
        value = value;          // fel!!
    }
så är det parametern value som får värdet value, ingenting händer med attributet value.

Vi har alltså hittills stött på tre sorters variabler:

  • lokala variabler, deklareras inne i operationer (även huvudprogrammet betraktas som en operation) och existerar bara inne i den operation de är deklarerade,
  • parametrar, fungerar precis som lokala variabler, men får startvärden när operationen startas (startvärdet får de vid anropet), och
  • attribut (tillståndsvariabler), som deklareras inne i en klass och finns i 'sitt' objekt så länge objekten finns kvar.
Vi kommer att träffa på några andra sorters variabler senare i kursen.

Inkapsling

Ett känt faktum är att en normal människa inte kan hålla mer än ett ganska begränsat antal detaljer åt gången i huvudet. Ju fler detaljer man får att hålla reda på, ju större är risken att man gör fel.

En av finesserna med objektorientering är att vi kan bespara en användare från många bekymmer genom att dölja detaljer i implementationen av en klass (med användare menar jag en annan programmerare som skall använda någon av våra klasser). På samma sätt som de flesta av oss struntar i exakt hur TV-n fungerar, bara den fungerar, vill en programmerare inte veta mer om hur ett objekt fungerar än vad som anges i klasspecifikationen.

För en användare av tärningsklassen räcker det att veta precis det som står i klasspecifikationen. Hon behöver inte veta att vi har ett heltalsattribut value, däremot måste hon veta hur man gör för att skapa, kasta och ta reda på utfallet av ett kast.

Att gömma detaljer för användaren kallas med ett finare ord för inkapsling, och det är en mycket viktig princip. Även om de exempel vi använder i kursen är väldigt små, är det viktigt att ni redan från början lär er att kapsla in på ett bra sätt!

Publika deklarationer - public

De attribut och operationer vi vill att användaren skall kunna se och använda deklarerar vi som public, dvs när vi deklarerar dem skriver vi det reserverade ordet public först: 

    public void roll() {
        // ...
    }
I tärningsexemplet vill vi att
  • konstruktorn,
  • roll(), och
  • getValue()
skall vara tillgängliga, vi skriver därför public i deklarationerna av var och en av dem.

När vi sedan genererar klasspecifikationen (i Java kan man göra det halvautomatiskt) kan vi välja att bara visa de publika deklarationerna.

Hemliga deklarationer - private

För att dölja våra attribut (och eventuellt några operationer) skriver vi det reserverade ordet private före dem i deklarationen: 
    class Die {
    
        private int value;
        
        public Die() {
            this.value = 1;
        }

        // ...resten av klassen...
Eftersom vi i regel deklarerar våra attribut som private kommer vi inte att se några attribut i klasspecifikationerna.

Vår (halv-) färdiga klass Die får följande utseende: 

    class Die {
    
        private int value;      // attribut, skyddat från omvärden
        
        public Die() {          // konstruktor, tillgänglig för alla
            this.roll();
        }
    
        public void roll() {    // kastar tärningen, tillgänglig för alla
            RandomNumberGenerator rng = new RandomNumberGenerator();
            this.value = rng.randInt(1,6);
        }
    
        public int getValue() { // ger antalet prickar, tillgänglig för alla
            return this.value;
        }
    }

Kort återkoppling och reflektion

Det kan, som repetition, vara nyttigt att i detalj studera det program vi skrev ovan, för att upprepade gånger kasta en tärning tills tärningssumman överskred 100. Fundera särskilt över hur exekveringen hoppar från huvudprogrammet in i operationerna på Die-objektet.

Huvudprogrammet hade följande utseende: 

    public static void main(String[] args) {
        Die die = new Die();
        int sum = 0,
            count = 0;
        while (sum < 100) {
            die.roll();
            sum += die.getValue();
            count++;
        }
        System.out.println("Jag behövde " + count + " kast.");
    }
och de programrader som kommer att exekveras blir: 
    Die die = new Die();  // konstruktorn i den nya tärningen startar:
               // inne i det nya objektet, konstruktorn: {
                      // 'this' refererar till det nya objektet:
                      this.value = 1;
                  }
    int sum = 0,
        count = 0;
    while (sum < 100) {
        die.roll();       // operationen roll i tärningen die anropas:
               // inne i die.roll() {
                      // 'this' refererar till tärningen die.
                      // 'rng' är en lokal variabel.
                      RandomNumberGenerator rng = new RandomNumberGenerator();
                      this.value = rng.randInt(1,6);
                  }
        sum += die.getValue();  // operationen getValue() i tärningen die anropas:
               // inne i die.getValue() {
                      // 'this' refererar till tärningen die:
                      return this.value;
                  }
        count++;
    }
    System.out.println("Jag behövde " + count + " kast.");

En liten förenkling

Det är lite klumpigt att skapa en ny slumptalsgenerator varje gång vi skall kasta tärningen, istället kan vi låta varje tärning ha en egen slumptalsgenerator (som lever kvar så länge tärningen lever kvar): 
    class Die {
    
        private int value;
        private RandomNumberGenerator rng;
        
        public Die() {
            this.rng = new RandomNumberGenerator();
            this.roll();
        }
    
        public void roll() {
            this.value = this.rng.randInt(1,6);
        }
    
        public int getValue() {
            return this.value;
        }
    }
Eftersom slumptalsgeneratorn är deklarerad som private så kommer ingen att se att den finns (annars skulle kanske någon börja fundera över varför den var deklarerad).
