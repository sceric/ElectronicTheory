Anteckningar till föreläsning 5 och 6

Under de första två veckorna har vi stiftat en första bekantskap med programspråket Java, vi har diskuterat några viktiga grunder såsom variabler, tilldelningar, objekt, klasser, referenser, if-, for- och whilesatserna. Vi kommer idag att tala om en del av de regler som gäller för Java-program.

Om grundläggande programuppbyggnad

Kommentarer i programkoden

Det är viktigt att de program vi skriver är lätta att läsa och förstå för andra, ett sätt att öka läsbarheten hos ett program är att skriva lämpliga kommentarer så snart något icke-trivialt skall göras.

Det finns i Java tre sorters kommentarer:

  1. Enradskommentarer, allt som skrivs på en rad efter //. 
        int a;  // Detta är en kommentar
    // Hela denna rad är en kommentar
  2. Flerradskommmentarer, allt som skrivs mellan /* och */, exempelvis: 
        int a = 1;
    /* Här inleds en längre kommentar
       som fortsätter på nästa rad. */
    int b = 2;
  3. Javadoc-kommentarer, en speciell sorts kommentar som används för att automatiskt generera klass-specifikationer, vi kommer att behandla denna sorts kommentarer när vi börjar implementera egna klasser, senare i kursen.
Gör det gärna till en god vana att skriva kommentarer i era program, tänk även på att ni själva kan behöva kommentarerna när ni skall läsa igenom era program några dagar efter att ni skrev dem!

Block

De satser som skrivs innanför klamrar, { och }, utgör ett block. Huvudprogrammet, public static void main(String[] args), består av ett yttre block, men även inne i if-, for- och while-satser har vi block (om vi sätter ut { och }, som vi skall göra!).

Exempel: I nedanstående programavsnitt har vi fyra block: 

    public static void main(String[] args) {
        // Vi är nu inne i huvudprogrammets yttre block.
        int i,n;
        n = Keyboard.readInt("Skriv in ett heltal: ");
        if (n <= 0) {
            // Detta block ligger innnanför det yttre blocket
            System.out.println("Det tal du angav var inte positivt");
        } else {
            // Även detta block ligger innanför det yttre blocket
            for (i = 1; i <= n; i = i + 1) {
                // Detta block ligger inne i blocket som börjar efter else.
                System.out.println(i);
            }
        }
    }
I ett block kan vi deklarera lokala variabler. De variabler vi hittills använt har varit deklarerade som lokala variabler i det yttre blocket i public static void main(...), men vi kan även deklarera lokala variabler inuti inre block.

I exemplet ovan använder vi bara räknaren i inne i else-satsen, vi kan därför deklarera i inne i else-satsen: 

    public static void main(String[] args) {
        int n;
        n = Keyboard.readInt("Skriv in ett heltal: ");
        if (n <= 0) {
            System.out.println("Det tal du angav var inte positivt");
        } else {
            int i;
            for (i = 1; i <= n; i = i + 1) {
                System.out.println(i);
            }
        }
        // Här är inte variablen i deklarerad.
    }
En variabels räckvidd (eng. scope) är det block den är deklarerad i, den existerar inte utanför. Vi kan alltså inte använda i i exemplet ovan efter att else-satsen är avslutad. Däremot kan vi alltid använda variabler som är deklarerade i omgivande block.

Exempel: Om vi vill låta två variabler byta värden med varandra måste vi lagra ett av värdena i en mellanlagringsvariabel. Om vi vill läsa in två heltal, a och b, och låta a bli det största av dem, kan vi skriva: 

    int a,b;
    a = Keyboard.readInt("a: ");
    b = Keyboard.readInt("b: ");
    if (b > a) {
        // Variablerna a och b måste byta värde,
        // värdet på a mellanlagras i variabeln temp.
        int temp;
        temp = a;
        a = b;
        b = temp;
    }
    // Här behöver vi inte längre variabeln temp.
Variabeln temp är bara deklarerad inne i if-satsen.

I slutet av följande avsnitt kommer vi att visa en särskild regel för räckvidden för räknarvariabler i for-satser.

Deklarationer och startvärden

När vi deklarerar våra lokala variabler blir de oinitierade, men vi kan även ge dem startvärden. Vi ger dem startvärden genom vanliga tilldelningar:

Exempel: Deklarationerna 

    int a=0, b=a+1, c;
ger oss tre heltalsvariabler, a, b och c, där två av variablerna tilldelas värden (a=0 och b=1) medan c är oinitierad. Lägg märke till att vi kan använda värdet av a när vi initierar b, initieringen går från vänster till höger.

I Java har vi i princip fri layout (fast vi kommer strax att allvarligt inskränka era friheter, se avsnittet om kodkonventioner!), så deklarationerna ovan kan även skrivas: 

    int a=0,
        b=a+1,
        c;
Denna form är bra om vi vill förklara vad variablerna används för: 
    int nbrOfValues = 0,    // antal inlästa värden
        value = 0,          // aktuellt värde
        maxValue = 0;       // största värde
I många programspråk skall alla deklarationer göras först i programkoden, i Java kan man deklarera variabler var som helst. Var man placerar sina deklarationer är ofta en fråga om tycke och smak, vissa föredrar att alla variabler deklareras överst i programkoden (så att de snabbt kan hitta deklarationen), andra deklarerar sina variabler först när de behövs (så att man slipper hoppa med blicken när man läser programkoden).

Ett särskilt fall är deklarationer i for-loopar, om vi deklarerar och initierar en variabel i for-satsens huvud så anses den deklarerad inne i for-satsens block: 

    for (int i = 1; i <= 10; i = i + 1) {
        // i är deklarerad bara inne i detta block
    }
    // här är inte i deklarerad längre!

Kontrollfrågor

  1. Vilka variabler är deklarerade på de markerade raderna nedan? 
        int a = 1,
        b = 2;
    for (int i = 1; i <= 10; i = i+1) {
        int c = 3;
        // vilka variabler är tillgängliga här?
    }
    // vilka variabler är tillgängliga här?

Några varianter på tilldelningssatsen

Den allmäna formen för en tilldelningssats är: 
    value = uttryck;
Det finns några speciella tilldelningar som fått en förenklad form i Java. Om vi vill öka en variabel value med ett givet värde, exempelvis increment, kan vi skriva 
    value = value + increment;
Eftersom det är så vanligt att man vill öka värdet på en variabel på detta vis finns en speciell kortform: 
    value += increment;
På samma sätt finns en uppdateringstilldelning för de andra räknesätten, vi kan skriva 
    value -= change;   // istället för value = value - change;
    value *= factor;   // istället för value = value * factor;
    value /= divisor;  // istället för value = value / divisor;
Det finns ytterligare en förenkling, eftersom man ofta ökar en variabels värde med 1 (exempelvis i for-loopar!), så kan vi istället för 
    i += 1;
skriva 
    i++;
På samma sätt kan vi minska värdet på en variabel med 1 genom att skriva 
    i--;
Det finns två former av ++ och --, en prefix- och en posfix-form (den ovan). Vi kommer att beskriva prefix-formen senare i kursen.

Med hjälp av ++ kan vi skriva for-satsen på ett enkelt sätt: 

    for (int i = 1; i <= n; i++) {
        // dessa satser upprepas n gånger
    }
Denna form av for-sats, med en lokal räknarvariabel och uppdatering med ++-operatorn, kommer vi att använda väldigt ofta i kursen.

Olika typer

Java är ett starkt typat språk, vilket innebär att alla variabler och uttryck måste ha en bestämd typ. När ett program kompileras kontrollerar kompilatorn att typerna i alla uttryck överensstämmer, och ger felutskrifter om något uttryck är feltypat. På detta vis undviker man många onödiga programmeringsfel.

I Java skiljer man mellan primitiva typer och referenstyper. De primitiva typerna är de som ryms i en variabel (heltal, reella tal, tecken etc), referenstyperna är referenser till objekt (och vektorer, som vi skall behandla om någon vecka).

Primitiva typer

Bland de primitiva typerna skiljer man mellan numeriska typer och typen boolean, som används för att hantera logiska värden (typen är uppkallad efter den engelske 1800-talslogikern George Boole).

Heltalstyper

Det finns inte mindre än fyra vanliga heltalstyper (samt char, som rent tekniskt är en heltalstyp, men som används för att lagra tecken). De fyra typerna är
  • byte, som kan anta värden i intervallet -128 .. 127, dessa tal rymms i 8 bitar
  • short, som kan anta värden i intervallet -32 768 .. 32 767 (16 bitar)
  • int, som kan anta värden i intervallet -2 147 483 648 .. 2 147 483 647 (32 bitar)
  • long, som kan anta värden i intervallet -9 223 372 036 854 775 808 .. 9 223 372 036 854 775 807 (64 bitar)
Det är dock inte alls säkert att Java-systemet använder 8, 16, 32 respektive 64 bitar för att lagra tal av de olika typerna.

När vi vet storleksordningen på våra variabler kan vi välja vilken av heltalstyperna vi skall använda, i kursen kommer vi mestadels att använda heltal av typen int, eftersom de räcker i de flesta sammanhang.

Operationer på heltal
För heltal har vi bland annat följande operationer (det finns fler, men vi använder dem inte i denna kurs):
  • 'Unärt' plus och minus, dvs vi kan skriva -4 eller +3

  • 'Multiplikativa operationer': *, /, %:

    Om vi dividerar två heltal får vi som resultat ett heltal, avrundat nedåt (mot 0). Uttrycket 3/2 får alltså värdet 1, även -3/2 får värdet 1.

    Operatorn % ger resten vid division, 7 % 4 ger värdet 3, -7 % 4 ger värdet -3.

  • 'Additiva operationer': + och -.

  • 'Öknings-operationen': ++ (se avsnittet om alternativa tilldelningar).

  • Omvandling till sträng: när vi skall skriva ut ett heltal omvandlas talet till en sträng. Vi kommer att diskutera detta mer senare i kursen.
Prioritetsordningen för heltalsoperationerna är
  1. unärt + och -
  2. *, /, %
  3. +, -
(Även ökningsoperationen ger ett värde, och skulle egentligen placeras in i prioritetsordningslistan ovan, men vi väntar med det till senare i kursen).

Multiplikation, division och rest går alltså före addition och subtraktion, precis som vi är vana. Med hjälp av parenteser kan vi kringgå prioritetsreglerna. Om vi vill att 1+2*3 skall bli 9 måste vi skriva uttrycket som (1+2)*3.

När prioriteten för operatorerna är lika räknas uttrycken från vänster till höger, det innebär att man måste vara lite försiktig, se exemplen nedan: 

    a = 1/2*3;
Här har / och * samma prioritet, så vi räknar från vänster till höger. Eftersom vi dividerar två heltal, 1 och 2, så får vi heltalsdivision, vilket ger resultatet 0. Multiplikationen med 3 ger inget, alltså får a värdet 0.

Även om variabeln till vänster om tilldelningstecknet är av reell typ kommer beräkningarna att utföras med heltalsdivision om argumenten är heltal: 

    double x = 1/2*3.141592653589793;
kommer att ge värdet 0, eftersom den inledande divisionen blir en heltalsdivision. Det räcker dock att göra om endera av täljaren eller nämnaren till ett reellt värde för att få en reell division: 
    double x = 1.0/2*3.141592653589793;
ger värdet π/2.

Reella typer

Det finns två reella typer, en med ungefär 9 och en med ungefär 18 siffrors upplösning.
  • float: det till beloppet minsta värdet vi kan lagra i en float-variabel är 1.4E-45, det största värdet vi kan lagra är 3.4028235* 10^38.
  • double: det till beloppet minsta värdet vi kan lagra i en double-variabel är 4.9E-324, det största värdet vi kan lagra är 1.7976931348623157*10^308.
Vi kan ange reella tal med eller utan 10-potenser: 
    double x = 2.54e-6,
           y = 0.4e9,
           z = 1.5,
           t = 1;
betyder att x blir 2.54*10^(-6) (dvs 0.00000254) och y blir 400 000 000. Variablerna z och t blir 1.5 respektive 1.0.

Att ge en variabel ett float-värde är lite knepigare: 

    float f = 1.2;
är inte tillåtet eftersom Javasystemet betraktar 1.2 som ett double-värde (se mer om detta nedan, i avsnittet om typkonverteringar). Istället får vi skriva: 
    float f = 1.2f;
där f-et betyder att talet skall tolkas som ett float-tal (märkligt nog får vi inte detta problem när vi försöker lagra talet 1 i en byte-variabel).

Operationer på reella tal
För de reella talen har vi samma operationer som vi ovan beskrev för heltalen (det finns dock några heltalsoperationer som man inte kan utföra på reella tal, men dessa faller utanför kursen). Rest-operationen är definierad även för reella tal, men vi kommer bara att använda den för heltal.

Division med reella tal ger reella värden, så om vi skriver 

    double x = 1.0/2.0;
så får vi naturligtvis värdet 0.5 (eller, åtminstone ett tal som ligger väldigt nära 0.5). Det räcker att den ena av operanderna är reell för att vi skall få reell division. Vi kommer att diskutera aritmetik med reella tal även under rubriken "Konvertering mellan olika typer" nedan.

Typen char

Rent tekniskt definieras typen char som en numerisk typ, den kan anta värden som numeriskt kan tolkas som 0..65535 (ett två bytes Unicode-tecken).

De första 128 värdena (0..127) i motsvarar de ASCII-tecken som används i många andra programspråk. Det innebär att vanliga bokstäver har en speciell kod, några värden:

kod tecken
32  
.. ..
48 '0'
49 '1'
.. ..
65 'A'
66 'B'
.. ..
97 'a'
98 'b'

En char-variabel kan ges teckenvärden med hjälp av apostrofer: 

    char ch = 'a',        // ch får det numeriska värdet 97
         digitOne = '1',  // digitOne får det numeriska värdet 49
         space = ' ';     // space får det numeriska värdet 32
Vi kan använda de vanliga heltalsoperationerna på tecken, eftersom bokstäverna ligger efter varandra i Unicode-ordning, så vi kan exempelvis skriva ut bokstäverna 'a'..'z' med: 
    for (char ch = 'a'; ch <= 'z'; ch++) {
        System.out.print(ch);
    }

Boolean

Vi kan lagra logiska värden i variabler av typen boolean. Det finns två olika logiska konstanter, true och false, och vi kan deklarera två logiska variabler, found och ok, genom att skriva: 
    boolean found = false,
            ok;
där found får startvärdet false, medan ok blir oinitierad.

De villkor vi använt i if-satser, for-satser och while-satser har alla typen boolean. Vi kan därför skriva 

    int a = Keyboard.readInt("a: "),
        b = Keyboard.readInt("b: ");
    boolean aIsBiggest;
    aIsBiggest = a > b;
där jämförelsen a > b är antingen true eller false, och värdet lagras i den logiska variabeln aIsBiggest.

Vi kommer att utnyttja logiska variabler senare i kursen, bland annat i samband med sökning i vektorer (som vi kommer att behandla nästa vecka).

För sammansatta villkor kan vi använda följande tre logiska operatorer:

  • logiskt och, skrivs &&,

  • logiskt eller, skrivs ||, och

  • logisk negation, skrivs !.
där prioritetsordningen är
  1. !
  2. &&
  3. ||
De logiska operatorerna förklarars enklast med exempel:
  • Uttrycket a > b && a > c är sant när både a > b och a > c, dvs när a är större än både b och c.

  • Uttrycket a > b || a > c är sant när antingen a > b eller a > c, dvs när a är större än någon av b och c.

  • Uttrycket !(a > b) är sant när inte a > b, dvs när a <= b.
Exempel: Om vi vill se att 1 ≤ n ≤ 10 måste vi testa både att 1 ≤ n och att n ≤ 10. Med hjälp av &&-operatorn kan vi skriva: 
    if (1 <= n && n <= 10) {
        System.out.println("n ligger i intervallet 1..10");
    }
Vi kan formulera villkoret ovan lite annorlunda med hjälp av eller-operatorn: 
    if (n < 1 || n > 10) {
        System.out.println("n ligger inte i intervallet 1..10");
    }
Villkoret ovan kan skrivas om med negationsoperatorn: 
    if (!(1 <= n && n <= 10)) {
        System.out.println("n ligger inte i intervallet 1..10");
    }
Lägg märke till att vi måste har en parentes i uttrycket ovan, annars hade negationen inte opererat på hela och-uttrycket (i själva verket hade vi fått ett kompileringsfel, eftersom prioriteten för negationen går före även jämförelsen).

Konvertering mellan olika typer

Eftersom typen long innehåller alla de värden som finns i typen int (och dessutom många fler), så är det inga problem med att lagra värdet av en int-variabel i en long-variabel - vi säger att long är en större typ än int. 
    int n = 12;
    long m = n;   // denna tilldelning ger inga problem.
Vid tilldelningen på den andra raden omvandlas värdet n till ett long-värde innan det lagras i variabeln m.

Om vi försöker göra tvärtom, tilldela variabeln n värdet av variabeln m kan vi däremot få problem - ett long-tal kan vara för stort för att rymmas i en int-variabel. Programraderna: 

    long m = 12;
    int n = m;
ger ett kompileringsfel som säger att vi inte får lagra ett long-värde i en int-variabel.

Om vi vet att värdet i long-variabeln inte är större än att det skulle rymmas i en int-variabel, så kan vi typkonvertera (eng. type cast) värdet av m till ett int innan vi gör tilldelningen. Det gör vi genom att skriva 

    long m = 12;
    int n = (int) m;
Allmänt typkonverterar man genom att skriva ett typnamn inom parentes före ett uttryck:

(<typnamn>) uttryck;

Tilldelningen 

    double x = 1;
går fint, double är en större typ än int, så 1:an omvandlas till det reella värdet 1 innan det lagras i x.

Vi kan använda typkonvertering för att lösa problemet vi hade med heltalsdivision ovan: 

    double x = (double)1/2*3;
konverterar värdet 1 till ett double-värde (1.000...) innan divisionen utförs. Eftersom detta uttryck är reellt kommer reell division att utföras, och uttryckets värde blir 1.5.

Viss försiktighet bör iakttagas: 

    double x = (double)(1/2*3);
ger x värdet 0.0, typkonverteringen appliceras inte förrän uttrycket inom parentesen beräknats (och blivit 0, precis som ovan).

Anrop av standardfunktioner

Det finns ett enkelt sätt att beräkna värdet av olika standardfunktioner, vi har funktionerna
  • long Math.round(double x) som ger värdet på x avrundat till närmaste heltal (att det står long framför Math.round... beror på att operationen returnerar ett long-värde)

  • long Math.floor(double x) som ger värdet på x trunkerat till närmaste heltal, dvs decimalerna stryks

  • double Math.sqrt(double x) som ger kvadratroten ur x

  • double Math.exp(double x) som ger exponentialfunktionens värde i x (som ett double-värde)

  • double Math.log(double x) som ger naturliga logaritmen för x

  • double Math.sin(double x) som ger sin(x), där x mäts i radianer

  • double Math.cos(double x) som ger cos(x), där x mäts i radianer

  • double Math.tan(double x) som ger tan(x), där x mäts i radianer

Den matematiska konstanten pi (π) skrivs Math.PI (utan parenteser!).

Exempel: För att beräkna kvadratroten ur ett inläst värde kan vi skriva: 

    double x = Keyboard.readDouble("Ange x: ");
    double rot = Math.sqrt(x);
    System.out.println("Kvadratroten ur " + x + " är " + rot);
Att Math-operationerna returnerar double- eller long-värden, beror på att man vill kunna arbeta med maximal upplösning och maximalt stora heltal.

Om vi själva använder vanliga heltal (int) kan vi få vissa problem, när vi anropar exempelvis Math.round(...)-operationen får vi tillbaka ett long-värde. Detta värde kan inte lagras i en int-variabel utan konvertering: 

    double x = Keyboard.readDouble("Ange x: ");
    int n = (int) Math.round(x);
Skulle det inlästa värdet på x vara för stort för att rymmas i en int så kommer vi att få ett konstigt värde i n, dock får vi inget exekveringsfel (dvs programmet bryts inte).

Kodkonventioner

Företaget Sun (som ligger bakom språket Java) har gett ut 'kodkonventioner', en uppsättning regler för hur man bör skriva sina Javaprogram. Bland anledningarna att ha en kodkonvention nämner de:
  • 80% av livstidskostnaden för datorprogram går till underhåll av programkoden.
  • Nästan inga program underhålls hela sin livstid av den ursprunglige programmeraren.
  • Kodkonventioner ökar läsbarheten och gör det möjligt för programmerare att förstå ett program snabbare och bättre.
Vi vill att ni i denna kurs försöker följa denna standard, inte minst för er egen skull. Genom att följa den kommer ni förmodligen att slippa många timmars onödigt felsökande (det kan säkerligen bli en hel del felsökning ändå!). Det är framförallt följande punkter vi vill att ni skall följa i början av kursen:
  • Enheten för indragningar i programkoden är 4 mellanslag.
  • Använd förklarande variabelnamn.
  • Använd alltid klamrar, { och } i if-, for- och while-satser.
  • Följ indragningsanvisningarna nedan.
Lägg dessutom gärna in tomma rader för att öka läsbarheten hos era program. Tom rad kan vara lämpligt före en kommentar eller före programrader som löser en avgränsad deluppgift.

Indragningsanvisningar

När vi börjar ett nytt block skall vänsterkantens indragning ökas med 4 mellanslag. Den klammer som "öppnar" blocket skall stå på samma rad som den if-, else-, for- eller while-sats som den hör till. Reglerna för hur den avslutande klammern skall sättas framgår av nedanstående exempel (lägg märke till att den alltid hamnar rakt under if, else, for eller while):

if-satsen

    if (villkor) {
        satser;
    }

    if (villkor) {
        satser;
    } else {
        satser;
    }

    if (villkor) {
        satser;
    } else if (villkor) {
        satser;
    } else if (villkor) {
        satser;
    } else {
        satser;
    }

for-satsen

    for (initiering; villkor; uppdatering) {
        satser;
    }

while-satsen

    while (villkor) {
        satser;
    }
Om vi skriver ett block inuti ett annat skall det inre blocket dras in enligt samma regler som det yttre blocket: 
    for (int i = 1; i <= 100; i++) {
        System.out.print(i + " ");
        if (i % 10 == 0) {
            System.out.println();
        }
    }

Om kompileringsfel

Under föreläsningen kommer vi att tala om hur man tolkar kompilatorns felutskrifter.
