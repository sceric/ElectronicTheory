Angående förra veckans övning

Många har i övning 10 använt det reserverade ordet super för att referera till operationer på det aktuella objektet, exempelvis i operationen walk() i klassen MazeTurtle: 
    public void walk() {
        ...
        super.forward(1);
        ...
        super.left(90);
        ...
    }
Operationerna forward(int) och left(int) ligger mycket riktigt i superklassen till klassen MazeTurtle, men det är inte nödvändigt att skriva super. Om vi skriver this.forward(1), eller bara forward(1), anropas den forward(int)-operation som ligger närmast (eftersom det inte finns någon i MazeTurtle anropas automatiskt den i faderklassen).

Normalt skriver man bara ut super när det verkligen behövs (i regel när man "överrider", dvs skriver en operation med samma signatur som en ärvd operation, och vill anropa den ärvda operationen).

Om vi i klassen MazeTurtle skriver en modifierad version av forward-operationen (exempelvis för att räkna antalet steg), och anropar super.forward(1), så kommer vi inte att utnyttja den utvidgade klassens fulla kapacitet (dvs den kommer inte att räkna stegen).

Ett fel som många gör är att deklarera lokala variabler som private eller protected: 

    public void sample() {
        private int a;    // Fel, a är en lokal variabel.
        // ...
    }
Alla lokala variabler är oåtkomliga utifrån, de är inte ens åtkomliga inom klassen, bara inne i den operation de är deklarerade i. De kan därför inte deklareras som private, protected eller public.

Referenser och parametrar

Vi har tidigare sagt att parametrarna till en operation väsentligen fungerar som lokala variabler, men att de vid anrop av operationen får de startvärden som anges vid anropet (övriga lokala variabler får inget startvärde).

Detta innebär att en ändring av värdet på en parameter inte påverkar något annat än värdet på parametern inne i operationen. Med klassen Sample: 

    class Sample {
     
        public void op(int a) {
            // ...
            a = 1;       // ändrar värdet på parametern a för resten av operationen
            // ...
        }
    }
skulle vi i huvudprogrammet: 
    public static void main(String[] args) {
        Sample s = new Sample();
        int b = 3;
        s.op(b);
        System.out.println(b);
    }
få utskriften 3, den variabel vi skickar in som parameter ändras inte.

Om vi däremot skickar in en referensvariabel som parameter, så kan vi ändra det värde som den refererar till. I följande exempel kommer sköldpaddan som t refererar till att ändra tillstånd, däremot kommer referensvariabeln t inte att ändras (regeln är alltså fortfarande att den variabel vi skickar in inte ändras!). 

    class TurtleTaxi {

        public void drive(Turtle t, int x, int y) {
            t.jumpTo(x,y);      // ändrar objektet som t refererar till,
                                // denna ändring märks även efter att
                                // operationen avslutats
            t = null;           // ändrar värdet på parametern, denna
                                // ändring märks inte efter att operationen
                                // avslutats (denna sats finns med bara
                                // som exempel, den är totalt meningslös!)
        }
    }
När vi anropar drive i programmet 
    Turtle t = new Turtle(w,100,100);
    TurtleTaxi taxi = new TurtleTaxi();
    taxi.drive(t,250,250);
så flyttas den sköldpadda som variablen t refererar till, men referensvariablen referar fortfarande till samma sköldpadda.

Eftersom vektor-variabler väsentligen är referenser till vektorobjekt kan värdet på en vektor ändras i en operation, vektorvariabeln kommer dock även efteråt att referera till samma vektor (som dock kan innehålla ändrade värden).

Om vi har klassen Sample som nedan: 

    class Sample {
     
        public void assign(int[] a, int value) {
            for (int i = 0; i < a.length; i++) {
                a[i] = value;
            }
        }
    }
och huvudprogrammet 
    public static void main(String[] args) {
        Sample s = new Sample();
        int[] v = {1,2,3,4,5};
        s.assign(v,2);
    }
så kommer samtliga element i vektorn v att sättas till 2.

Om static - klassattribut och klassoperationer

Redan från första övningen har ni använt ordet static, det är nu dags att förklara vad det betyder.

När vi skriver våra klasser deklarerar vi de attribut och operationer som skall finnas för varje objekt av klassen, dvs

  • varje objekt (instans av klassen) har en egen uppsättning av de attribut vi deklarerar (attributen kallas därför ibland instansvariabler), och

  • alla operationer utförs på ett givet objekt (vid anropet referar this till detta objekt)
Vi har dock använt attribut och operationer som inte följer detta mönster (utan att då gå närmare in på det):
  • När vi skall beräkna sin(x) skriver vi Math.sin(x). På vilket objekt utför vi operationen sin(double)?

  • När vi skriver ut skriver vi System.out.println("Hello"). På vilket objekt utförs operationen println(String)?
Svaret på den första frågan är att sin(double)-operationen utförs på Math-klassen i sin helhet, dvs det är inte en operation på ett objekt utan på klassen Math.

Man gör en operation till klassoperation genom att skriva det reserverade ordet static i deklarationen: 

class Math {

    public static double sin(double x) {
        // ...
    }
Vi kan nu anropa sin(double)-operationen direkt på klassen Math, utan att skapa något Math-objekt.

Svaret på den andra frågan är lite knepigare, println(String)-operationen utförs där på ett objekt som heter out, och är ett publikt klassattribut (eller klassvariabel) i klassen System!

I klassen System är detta attribut deklarerat (ungefär): 

class System {

    public static PrintStream out;

    // ...
}
Detta innebär att attributet out ägs av hela klassen System, inte av de enskilda System-objekten. På detta PrintStream-objekt utförs println-operationen. Det hela är dubbelt förvirrande första gången man ser det, attributet är inte skyddat, och det tillhör inget specifkt objekt.

Överkurs: Båda klasserna Math och System är speciella. Klassen Math fungerar som ett 'paket' för ett antal matematiska funktioner, man skapar aldrig något Math-objekt. Man skapar heller aldrig något objekt av klassen System, den används i princip som ett färdigt objekt. Man kan dock mycket väl ha statiska attribut och statiska operationer i klasser som används på vanligt sätt.

Om attribut i klassoperationer

Eftersom en klassoperation inte utförs på ett enstaka objekt, är de vanliga attributen inte tillgängliga - bara klassattributen kan användas. På samma sätt är bara klassoperationer tillgängliga, det finns ju inget this som vi utför operationen på: 
class Sample {

    public static int a;    // klassattribut
    public int b;           // vanligt attribut (instansvariabel)

    public void op1() {
        a = 1;      // OK, klassvariabeln a får ett värde
        b = 2;      // OK, instansvariabeln b i objektet this får ett värde
        op2();      // OK, anropar klassoperationen op2()
    }

    public static void op2() {
        a = 1;      // OK, klassvariabeln a får ett värde
        b = 2;      // Fel, instansattributet b finns bara i instansoperationerna
        op1();      // Fel, op1() är en operation på ett objekt, men när vi
                    // kör denna operation finns det inget this att anropa
                    // den på
    }
}
För att tydligt markera vad som är instansvariabler (vanliga attribut) och vad som är klassvariabler kan man i sina operationer i klassen Sample ovan markera instansvariabler med this.b och klassvariabler med Sample.a.

När man i klassoperationen op2() ovan skriver this.b = 2 blir det uppenbart att operationen är felaktig, det finns ju inget this eftersom operationen utförs på klassen själv.

Om att dela upp sina huvudprogram

Med hjälp av klassoperationer kan man dela upp sina huvudprogram utan att skapa nya objekt.

Om vi på flera ställen i ett program vill skriva ut en hel vektor kan vi skriva: 

    public class f14 {
    
        public static void main(String[] args) {
            int[] v = {5,2,3,5,6,1,2,3};
            System.out.println("Före sortering:");
            print(v);
            sort(v);
            System.out.println("Efter sortering:");
            print(v);
        }
    
        private static void sort(int[] v) {
            for (int i = 1; i < v.length; i++) {
                int pos = i;
                int value = v[pos];
                while (pos > 0 && v[pos-1] > value) {
                    v[pos] = v[pos-1];
                    pos--;
                }
                v[pos] = value;
            }
        }
    
        private static void print(int[] array) {
            for (int i = 0; i < array.length; i++) {
                System.out.println(i + ": " + array[i]);
            }
        }
    }

Vad betyder då deklarationen av huvudprogrammet?

Vi kan nu äntligen förklara vad deklarationen 
    class Sample {
    
        public static void main(String[] args) {
            // ....
        }
    }
egentligen betyder. Den säger att main är en publik operation på klassen Sample (när vi startar programmet har vi ju inte skapat något objekt av klassen), och att den:
  • inte returnerar något värde (den är av typen void), och
  • den har en parameter, en vektor med strängar.
Vektorn med strängar är de eventuella argument som gavs när programmet startades.

Om vi startar programmet Sample genom att skriva 

    java Sample Hej och hå
så kommer vektorn args att ha längden tre och innehålla strängarna "Hej", "och" och "hå".

Om variabler som inte kan ändra värde

Ibland vill man att variabler inte skall kunna ändra värde, man kan då deklarera dem final. Ett exempel på en sådan variabel är det publika attributet PI i klassen Math, det är deklarerat som 
    class Math {
    
        public static final double PI = 3.1415926535897932385;
    
        // ...
    }
Om det inte hade varit deklarerat som final hade vi i ett program kunnat skriva 
    Math.PI = 4;
och därmed ändrat värdet på pi!

Även lokala variabler kan final-deklareras: 

    public static void main(String[] args) {
        final int nbrOfGames = 13;
        // ...
    }

Klasserna String och StringBuffer

I språket Java finns två klasser för att hantera strängar: String och StringBuffer, dessa båda klasser beskrivs på ett utmärkt sätt i Per Holms bok, kapitel 12.

Strängar är objekt, men det finns i Java några väldigt bekväma sätt att skapa dem, exempelvis kan vi skriva: 

    String firstName = "Adam";
    String lastName = "Scott";
Strängobjekt är "immutables", dvs oföränderliga, men vi kan skriva: 
    String wholeName = firstName + " " + lastName;
för att slå samman flera strängar till en ny sträng. Denna typ av strängkonkatenering har vi utnyttjat oräkneliga gånger i kursen i samband med utskrifter: 
    System.out.println("Värdet på n är " + n);
När vi konkatenerar en sträng med något annat än en sträng (som i utskriften ovan), så konverteras automatiskt det andra värdet till en sträng.

Det finns ganska många operationer i klassen String, vi kommer framförallt att använda:

  • public int length(), som ger strängens längd,
  • public char charAt(int pos), som ger tecknet i position pos (som räknas från 0, precis som för vektorer),
  • public int compareTo(String other), som jämför två strängar med varandra (värdet är < 0 om this kommer före other i bokstavsordning, > 0 om this kommer efter other, och 0 om de båda strängarna är lika,
  • public boolean equals(String other), som är sann om de båda strängarna är lika,
  • public String toLowerCase(), som ger samma sträng, men med små bokstäver, och
  • public String toUpperCase(), som ger samma sträng, men med stora bokstäver.
Exempel:
För att lagra bokstäverna i en sträng i en vektor kan vi skriva: 
    String str = Keyboard.readLine();   // läser en rad från tangentbordet
    char[] ch = new char[str.length()];
    for (int i = 0; i < str.length(); i++) {
        ch[i] = str.charAt(i);
    }

Om deklaration av attribut

När vi deklarerar ett attribut kan vi, precis som när vi deklarerar en lokal variabel, ge variabeln ett startvärde. 

class A {

    private int n = 3;

    public A() {
        // här har attributet n redan värdet 3
    }
}
Om vi väljer att initiera sina attribut redan vid deklarationen eller i konstruktorn är en fråga om tycke och smak.

En villkorskonstruktion

Det finns i exempel 3 på sidan 196 en konstruktion som vi inte behandlat i kursen: 
    <villkor> ? <värde om villkoret sant> : <värde om villkoret falskt>
som är en typ av villkorssats. Om vi vill bestämma det minsta av två värden a och b kan vi skriva: 
    int smallest = a < b ? a : b;
istället för det lite klumpigare: 
    int smallest;
    if (a < b) {
        smallest = a;
    } else {
        smallest = b;
    }
Denna konstruktion behöver ni inte behärska, men den kan vara bra att känna till.
