Matriser

Tidigare har vi använt vektorer för att lagra flera värden i en variabel, de vektorer vi använde hade ett index. För att hämta det tredje värdet i en heltalsvektor v skrev vi v[2].

Ibland vill man använda flera index, antag exempelvis att vi vill lagra en digital bild (vi antar för enkelhets skull att den är svartvit, med ett visst antal nyanser av grått). Vi delar in bilden i punkter (små kvadrater), och låter varje punkt ha värden i en given gråskala:

Om vi låter 0 betyda vit och 255 betyda svart, kan vi uttrycka 256 olika nyanser av svart. Bilden kan alltså representeras av höjd*bredd heltal i en matris: 

    160, 160, 160,   0,   0
    200,  80,  80,  80,  80
    200,  80, 160, 255, 160
    200,  80, 255, 255, 160
    200,  80,  80,  80,  80
Vi deklarerar och skapar matrisen genom att skriva: 
    int width = Keyboard.readInt("Bildens bredd: "),
        height = Keyboard.readInt("Bildens höjd: ");
    int[][] pict = new int[height][width];
(Syntaxen är ganska naturlig, när vi deklarerar en endimensionell vektor med heltal skriver vi int[], nu skall vi ha en vektor med vektorer, alltså skriver vi [] efter int[], dvs int[][]. Vi får en hakparentes för varje index.)

Även flerdimensionella vektorer räknar sina index från 0, så värdet i andra raden, fjärde kolumnen skriver vi pict[1][3]:

Vi behöver inte skapa hela matrisen på en gång och vi kan ha olika många värden i de olika raderna, men det är överkurs. I denna kurs kommer alla matriser att vara rektangulära (och många dessutom kvadratiska, dvs med lika många rader som kolumner).

För att skriva ut bilden pict på en skärm med följande klasspecifikation: 

    specification Screen {

        Screen(int width, int height);

        clear();

        setValue(int row, int col, int value);
    }
kan vi gå igenom hela bilden, rad för rad, kolumn för kolumn: 
    Screen screen = new Screen(width,height);
    screen.clear();
    for (int row = 0; row < height; row++) {
        for (int col = 0; col < width; col++) {
            screen.setValue(row,col,pict[row][col]);
    }

Att besöka grannar till en ruta i en matris

Om vi vill jämna ut bilden kan vi ersätta samtliga punkter i bildens inre med medelvärdet av de omgivande punkterna (inklusive det egna värdet), grannarna till rutan med index (1,3) framgår av figuren:

Följande programrader beräknar medelvärdena kring samtliga punkter i bildens inre: 

    int[][] tmp = new int[height][width];
    for (int row = 1; row < height-1; row++) {
        for (int col = 1; col < width-1; col++) {
            // beräkna summan av värden runt pict[row][col]:
            int sum = 0;
            for (int dr = -1; dr <= 1; dr++) {
                for (int dc = -1; dc <= 1; dc++) {
                    sum += pict[row+dr][col+dc];
                }
            }
            tmp[row][col] = (int) Math.round((double)sum/8);
        }
    }
    pict = tmp;
Här är det några saker som bör noteras:
  • Konstruktionen med fyra nästlade for-satser är viktig, vi behöver två for-satser för att gå igenom varje ruta i matrisen, och två for-satser för för varje ruta att gå igenom samtliga grannar.

  • Lägg särskilt märke till de innersta två for-satserna, de gör att vi går i de tre rader och tre kolumner som ligger runt den aktuella rutan (row, col). De hade även kunnat skrivas: 
            // beräkna summan av värden runt pict[row][col]:
        int sum = 0;
        for (int r = row-1; r <= row+1; r++) {
            for (int c = col-1; c <= col+1; c++) {
                sum += pict[r][c];
            }
        }
        tmp[row][col] = (int) Math.round((double)sum/9);
    Vilket skrivsätt man använder är en smaksak.

  • Vi kan inte ändra på matrisen pict förrän efter att vi räknat ut medelvärden runt samtliga punkter, annars får vi fel medelvärden (vi måste alltså undersöka en ögonblicksbild av matrisen). Medelvärdena lagras i en temporär matris medan undersökningen pågår.

  • Det är lite knepigt att jämna ut punkterna i bildens kant, eftersom de inte har grannar på alla sidor. Vi har därför i exemplet inte brytt oss om att ändra punkterna i bildkanten.

  • Tilldelningen på den sista raden innebär bara att matrisvariabeln pict sätts att referera till den nya matrisen, dess gamla värde slängs bort automagiskt (vektorer och matriser är ju en slags objekt).

Veckans övning innehåller en uppgift som är väldigt besläktad med denna uppgift (vi kommer längre ner i texten att gå igenom ett sätt att göra detta programavsnitt bättre strukturerat).

Andra användningar av matriser

Vi kan även använda tvådimensionella vektorer för att lagra matematiska matriser, för att lagra en reell 3*3-matris kan vi skriva: 
    double[][] a = new double[3][3];
Att addera två reella 3*3 matriser, a och b är enkelt: 
    double[][]
        a = new double[3][3],
        b = new double[3][3],
        c = new double[3][3];
    // ...
    // ... rader där a och b får värden ...
    // ...
    for (int row = 0; row < 3; row++) {
        for (int col = 0; col < 3; col++) {
            c[row][col] = a[row][col] + b[row][col];
        }
    }

Mångdimensionella matriser (överkurs)

Ibland kan man ha nytta av matriser med mer än två index, antag till exempel att vi vill lagra alla bokstäver i en bok, och delar in boken i
  1. avsnitt,
  2. kapitel,
  3. stycken, och
  4. rader.
Vi skulle kunna lagra hela boken i en matris med fyra index: 

    char[][][][] book;
Det blir då väldigt enkelt att plocka fram det tredje tecknet på den fjärde raden i andra stycket i första kapitlet i det fjärde avsnittet, det finns i book[3][1][3][2]

Vi kommer dock inte att använda denna typ av matriser i denna kurs.

Mer om implementation av egna klasser

Strukturering av programkod med hjälp av operationer

Under övning 7 skulle ni skriva ett program i vilket två sköldpaddor irrar omkring i ett fönster, programmet skulle avbrytas när de båda sköldpaddorna kom närmre än 50 punkter ifrån varandra.

Med den givna klasspecifikationen för Turtle blev programmet ganska klumpigt, ni fick skriva något i stil med: 

    while ((t1.getX()-t2.getX())*(t1.getX()-t2.getX()) +
           (t1.getY()-t2.getY())*(t1.getY()-t2.getY()) > 50*50) {
        t1.left(rng.randInt(0,359));
        t1.forward(rng.randInt(1,5));
        t2.left(rng.randInt(0,359));
        t2.forward(rng.randInt(1,5));
    }
Programmet går att läsa, men det är otympligt (och då har vi ändå inte testat att båda sköldpaddorna befinner sig innanför fönstret). Betydligt enklare vore något i stil med: 
    while (t1.distanceTo(t2) > 50) {
        t1.randomStep(1,5);
        t2.randomStep(1,5);
    }
Eftersom vi numera själva skriver klassen Turtle kan vi lägga till de operationer vi vill, exempelvis de operationer som skulle göra programmet ovan möjligt att skriva.

Att dela upp program i mindre delar, som löser väl avgränsade deluppgifter, är en väldigt viktig programmeringsteknik. I exemplet ovan har vi infört två ytterligare operationer, och därigenom fått ett program som är betydligt enklare att läsa. (Nästa vecka skall vi se hur vi kan utvidga klassen Turtle utan att påverka samtliga Turtle-objekt.)

Uppdelning i 'interna' operationer

Klassen Image i exemplet ovan kan deklareras ungefär så här: 
    class Image {

        private int width, height;
        private int[][] pict;

        public Image(int width, int height) {
            // ...
        }

        // ...

        public void soften() {
            // ...
        }
    }
Operationen soften kan då implementeras: 
    public void soften() {
        int[][] tmp = new int[this.height][this.width];
        for (int row = 1; row < this.height-1; row++) {
            for (int col = 1; col < this.width-1; col++) {
                // beräkna summan av värden runt this.pict[row][col]:
                int sum = 0;
                for (int r = row-1; r <= row+1; r++) {
                    for (int c = col-1; c <= col+1; c++) {
                        sum += this.pict[r][c];
                    }
                }
                tmp[row][col] = (int) Math.round((double)sum/9);
            }
        }
        this.pict = tmp;
    }
men enklare vore att bryta ut beräkningen av medelvärdet runt ett givet bildelement: 
    public void soften() {
        int[][] tmp = new int[this.height][this.width];
        for (int row = 1; row < this.height-1; row++) {
            for (int col = 1; col < this.width-1; col++) {
                // beräkna summan av värden runt this.pict[row][col]:
                tmp[row][col] = this.averageAround(row,col);
            }
        }
        this.pict = tmp;
    }
där averageAround bara beräknar medelvärdet runt en given punkt i bilden.

Eftersom denna operation bara skall användas av operationer inne i Image-klassen behöver den inte vara public, bättre är att dölja den genom att deklarera den private: 

    private int averageAround(int row, int col) {
        int sum = 0;
        for (int r = row-1; r <= row+1; r++) {
            for (int c = col-1; c <= col+1; c++) {
                sum += this.pict[r][c];
            }
        }
        return (int)Math.round((double)sum/9);
    }
Det är mycket möjligt att vi får nytta av denna operation när vi implementerar någon annan operation på klassen Image, men även om den bara används av operationen soften() så har den fyllt sitt syfte genom att den gjort programkoden enklare.

När skall man ha attribut och när skall man ha lokala variabler?

Vi såg förra veckan tre sorters variabler:
  • attribut (kallas även tillståndsvariabler),
  • lokala variabler, och
  • parametrar (som är ett slags lokala variabler, men som får startvärden i operationsanropet).
Det är viktigt att skilja på de tre, attribut skall bara användas för att beskriva tillståndet hos ett objekt.

En del vill 'spara' in lokala variabler genom att deklarera dem som attribut istället, dvs istället för att ha de lokala variablerna i och j deklarerade i både op1() och op2() 

    class A {

        int a, b;

        public void op1() {
            int i,j;
            // ...
        }

        public void op2() {
            int i,j;
            // ...
        }
    }
så flyttar de ut dem: 
    class A {

        int a, b;

        int i,j;  // Beskriver inte tillståndet, men används i op1() och op2().
                  // Detta är våldsamt olämpligt!

        public void op1() {
            // ...
        }

        public void op2() {
            // ...
        }
    }
Detta är inte bra, det innebär att alla A-objekt släpar med sig två onödiga heltal (i och j), men vad värre är, det inbjuder till en otrevlig typ av fel (som om inte alla fel är otrevliga!) - se andra uppgiften nedan. Vi kommer att gå igenom uppgiften under föreläsningen.

Alltså: använd bara attribut till att beskriva tillståndet hos ett objekt.
